Cómo evitar reservas duplicadas con Spring Boot y SQL

20 nov 2026 · 4 min · #java#springboot#sql

En MiCancha, nuestra plataforma de reserva de canchas deportivas, el siguiente gran paso es el flujo de reserva. Antes de programarlo, me tocó estudiar el problema más importante, que no es visual: dos personas no pueden reservar la misma cancha a la misma hora. Así es como lo voy a abordar en el backend con Spring Boot.

1. La regla del cruce de horarios

Dos reservas se cruzan cuando una empieza antes de que la otra termine y termina después de que la otra empiece. En SQL se escribe así:

SELECT COUNT(*) FROM reserva
WHERE losa_id = :losaId
  AND fecha = :fecha
  AND hora_inicio < :horaFin
  AND hora_fin    > :horaInicio;

Si el resultado es mayor que 0, el horario ya está ocupado.

2. Validar en el backend, no solo en la pantalla

Deshabilitar un botón en el frontend ayuda, pero no basta. La validación definitiva debe vivir en el servicio:

@Transactional
public Reserva crear(ReservaDTO dto) {
    boolean ocupado = repo.existeCruce(dto.losaId(), dto.fecha(),
                                       dto.horaInicio(), dto.horaFin());
    if (ocupado) {
        throw new HorarioNoDisponibleException("La losa ya está reservada en ese horario");
    }
    return repo.save(dto.toEntity());
}

3. Índices para que la consulta sea rápida

Como esta consulta se ejecuta en cada reserva y en cada búsqueda de disponibilidad, conviene un índice compuesto:

CREATE INDEX idx_reserva_losa_fecha ON reserva (losa_id, fecha);

Lo que me llevo

  • Primero hay que escribir la regla de negocio en palabras y después en código.
  • El backend es la única fuente de verdad.
  • Optimizar SQL no siempre es complicado: a veces basta con un buen índice.
Como en el aula: si puedes explicarlo simple, puedes programarlo bien.
